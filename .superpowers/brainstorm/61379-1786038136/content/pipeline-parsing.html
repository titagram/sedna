Sezione 3 — Pipeline di parsing e strutturazione

Un solo inventario, parser strutturali diversi per famiglia, due percorsi semantici e una validazione comune.

Flusso incrementale
1. Inventario
hash, formato, asset, path, stato
2. Classificazione
lesson, walkthrough, cheatsheet, stub, excluded
3. Parsing strutturale
heading, paragrafi, liste, tabelle, code block, immagini
4. Segmentazione logica
unità coerenti, non finestre di token
↓
Percorso reference
concept → metodologia → precondizioni → evidenza attesa → avvertenze → capability ref
Percorso case study
stato → osservazione → ipotesi → azione → output/evidenza → nuovo stato
↓
5. Normalizzazione
placeholder, phase, access, servizi, capability
6. Validazione
schema, provenance, inferenze, flag, contraddizioni
7. Emissione
JSON/JSONL, YAML revisionato, indice ricostruibile
Parser per famiglia
  • HTB scrape: rimuove sidebar, domande, footer e modali.
  • Obsidian/Academy: conserva wiki-link, tabelle e asset locali.
  • GitHub walkthrough: conserva ordine, code block, output e screenshot.
  • Stub/flag-only: classifica e non estrae conoscenza decisionale.
Controlli anti-allucinazione
  • ogni campo estratto ha source span o è marcato inferred;
  • flag, IP e callback non entrano nell'indice strategico;
  • un case study non genera automaticamente una regola;
  • record incompleti finiscono in quarantena con motivo;
  • regole promosse solo dopo revisione o più fonti concordanti.

Incrementalità

Il manifest conserva hash della sorgente, versione dello schema, parser e modello di estrazione. Un nuovo writeup o una modifica rielabora soltanto il documento interessato e gli eventuali draft di regole che lo citano.
