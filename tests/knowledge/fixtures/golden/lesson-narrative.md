# Establish the target surface

Begin with low-impact observations and record where every hostname came from. A useful inventory distinguishes evidence from assumptions, notes the time of collection, and avoids treating one source as authoritative. Compare DNS, certificate, and application clues before deciding that an asset belongs to the target.

## Form a testable hypothesis

Translate the observations into a narrow question before using an active technique. State what result would support the hypothesis, what would contradict it, and which prerequisite must remain true. This keeps the next action tied to evidence instead of habit or a remembered walkthrough.

## Interpret negative evidence

A failed request does not prove that a service is absent. Check whether routing, authentication, timing, or the chosen vantage point could explain the result. Preserve the failure because it can eliminate a branch or reveal that an earlier assumption was too strong.

## Decide when to change course

Stop repeating an approach when it adds no new evidence. Revisit the inventory, rank the remaining explanations by fit and cost, then choose the smallest discriminating test. The lesson is a decision pattern, not a fixed sequence of commands.
