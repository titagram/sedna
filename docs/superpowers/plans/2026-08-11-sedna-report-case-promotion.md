# Sedna M6C Report and Verified Case Promotion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a terminal, verified Sedna engagement into an immutable private operational report and a sanitized, provenance-backed canonical case that can be retrieved in later engagements, while supporting safe rejection, reopen, supersession, and revocation.

**Architecture:** Build M6C on the M6A `sedna.engagement` event journal and the M6B `PlanningService.settle_pending_evidence` boundary. Report JSON is an immutable snapshot committed with the final close event; Markdown is a deterministic, repairable rendering of that JSON. A private `JournalPromotionAdapter` compiles a symbolized journal snapshot into an immutable Markdown source plus line-to-event provenance map, passes only that descriptor-confined source through the existing semantic compiler under a case-required acceptance profile, and coordinates canonical/index publication or fail-closed revocation through replayable saga events.

**Tech Stack:** Python 3.11–3.13, Pydantic 2.13.4, Markdown-it-py 3.x, existing Sedna append-only JSONL journal, descriptor-relative POSIX IO and `flock`, existing semantic extractor/critic/repair pipeline, SQLite FTS5 projection, pytest 8.x, pytest-asyncio, Ruff 0.15.10

## Global Constraints

- M6A and M6B are hard prerequisites. Begin M6C only after their public contracts and tests pass.
- Keep the zero-configuration root exactly `<active-host-home>/knowledge/sedna`; do not add a new root, environment variable, or storage migration.
- M6A, M6B, and M6C are one product feature release: the package, plugin manifest, and
  `src/sedna/__init__.py` version remain exactly `0.2.0` throughout M6. M6B/M6C verify synchronization
  but do not invent sub-milestone product version bumps.
- Use `sedna.engagement.EngagementJournalService`, `JournalRevision`, and `EngagementSnapshot` as the public journal facade and models; do not replace or rename them.
- Invoke `PlanningService.settle_pending_evidence` before close, verify, reject, reopen, or report.
  Promotion consumes only the exact durable `closed_verified` snapshot whose verification path was
  already settlement-backed; it does not invent a second `promote` settlement reason.
- Only a closure barrier with `closure_ready=True` may commit `report_generated` and `engagement_closed`.
- Store flags, engagement credentials, raw executed commands/arguments, rendered previews, and
  proof values only inside the engagement-private layer: authoritative journal/evidence sidecars,
  derived private logbooks, and immutable private report snapshots. Canonical promotion may retain only sanitized symbolic command
  templates whose target/credential placeholders are unresolved and whose status is
  `requires_validation`; never place raw values or case-local bindings in promotion Markdown,
  provenance prose, FTS, or ordinary retrieval responses.
- Report JSON is immutable after its event-bound commit. Markdown is a deterministic derivative of that exact JSON and may be regenerated byte-for-byte without changing report revision.
- A missing or corrupt event-bound report JSON is repaired only by `generate_report_revision` at a later immutable revision; never rewrite the committed JSON path. A missing/corrupt Markdown derivative is repaired separately by `regenerate_markdown` from the exact valid JSON and recorded renderer version.
- Promotion requires `closed_verified` at an exact journal sequence/hash. `closed_unverified` may report but cannot publish canonical knowledge.
- The `JournalPromotionAdapter` is internal. It accepts no caller-supplied path, source ID, namespace, `PreparedSource`, or arbitrary source bytes.
- Use the dedicated namespace `journal-promotion` and a stable UUIDv5 source identity derived from the engagement UUID, not its display name, target, report revision, or local path.
- Public `sedna_learn_local` must continue rejecting any source that overlaps the knowledge root. M6C must not introduce a public internal-learning bypass.
- Every committed promotion source and provenance map is immutable. A later attempt allocates `promotion-vN+1` and never rewrites `promotion-vN`.
- Canonical currentness for `journal-promotion` requires descriptor-confined physical SHA-256 verification of both committed source and provenance map on every semantic snapshot/currentness boundary.
- The semantic acceptance profile for journal promotion must require at least one `KnowledgeCase` before any verified bundle is persisted.
- Use one promotion extractor, one isolated critic, at most one repair, and one final critic. A second rejection is a typed failure and publishes nothing.
- Treat journal text, tool output, web content, prior LLM output, source-registry content, commands, and canonical excerpts as untrusted data.
- Do not hold a journal, canonical repository, or SQLite lock across an LLM call, index rebuild, external search, or host tool call.
- Preserve the non-coercive host boundary: M6C generates reports and knowledge; it does not invoke security tools or replace Hades/Hermes authorization and `/learn` behavior.
- Do not add SysReptor integration, vector retrieval, deterministic semantic scoring, model-weight training, or the adversarial roleplay skill in M6C.
- Use `apply_patch` for hand-written changes, TDD for every behavior, and small commits at each task boundary.

```python
def commit_report_snapshot(
    self,
    engagement_id: UUID,
    report: OperationalReport,
    markdown: str,
    *,
    expected_revision: JournalRevision,
) -> ReportCommitResult:
    report = OperationalReport.model_validate(report.model_dump(mode="json", warnings="error"))
    expected_markdown = render_operational_report(report)
    if markdown != expected_markdown:
        raise ValueError("report Markdown does not match its immutable JSON snapshot")
    json_bytes = _canonical_json_bytes(report)
    markdown_bytes = markdown.encode("utf-8")
    if len(json_bytes) > MAX_REPORT_JSON_BYTES:
        raise ValueError("report JSON exceeds immutable report budget")
    if len(markdown_bytes) > MAX_REPORT_MARKDOWN_BYTES:
        raise ValueError("report Markdown exceeds immutable report budget")
    with self._engagement_lock(engagement_id):
        snapshot = self._snapshot_locked(engagement_id)
        existing = self._matching_committed_report_locked(
            snapshot,
            report=report,
            expected_revision=expected_revision,
            json_bytes=json_bytes,
            markdown_bytes=markdown_bytes,
        )
        if existing is not None:
            return existing
        self._require_revision(snapshot.revision, expected_revision)
        self._require_report_matches_ready_closure(snapshot, report)
        relative_json = f"engagements/{engagement_id}/reports/report-v{report.report_revision}.json"
        relative_md = f"engagements/{engagement_id}/reports/report-v{report.report_revision}.md"
        self._write_immutable_or_matching(relative_json, json_bytes, mode=0o600)
        self._write_derived_or_matching(relative_md, markdown_bytes, mode=0o600)
        self._fsync_confined_directory(f"engagements/{engagement_id}/reports")
        ref = ReportRef(
            report_id=report.report_id,
            report_revision=report.report_revision,
            json_relative_path=relative_json,
            json_sha256=sha256(json_bytes).hexdigest(),
            markdown_relative_path=relative_md,
            markdown_sha256=sha256(markdown_bytes).hexdigest(),
            renderer_version=REPORT_RENDERER_VERSION,
            journal_revision=expected_revision,
        )
        appended = self._append_batch_locked(
            engagement_id,
            (
                report_generated_draft(ref, generation_reason="closure"),
                engagement_closed_draft(snapshot, ref),
            ),
            expected_revision=expected_revision,
        )
        return ReportCommitResult(report=ref, snapshot=appended.snapshot)
```

Implement `_write_immutable_or_matching` and `_write_derived_or_matching` with retained descriptors, `O_NOFOLLOW`, regular-file checks, temp-file fsync, atomic rename, and directory fsync. Existing exact orphan bytes are reusable before an event; mismatched bytes fail closed. The JSON helper refuses to rewrite an event-bound target. The Markdown helper may recreate a missing derived file only from validated JSON and the recorded renderer version.

Before either final file rename, write and fsync one descriptor-confined
`reports/.report-transaction.json` intent containing the engagement/report IDs, expected revision,
both digests, renderer/generation reason, and internally derived final paths. Every repository append
checks this intent while holding the engagement lock. An exact `commit_report_*` retry completes or
returns the transaction. A different later append first atomically moves any unbound final files to
`reports/orphans/<intent-id>-<digest>/` and fsyncs, then appends one atomic journal batch
`[report_commit_abandoned, *caller_drafts]` against the caller's original expected revision. It
clears/fsyncs the intent only after that batch. Retry recognizes the exact event-bound abandonment
before ordinary stale-CAS rejection and returns the caller batch idempotently. The abandonment
payload binds the exact canonical draft envelope (actor, lane, type, payload, idempotency metadata)
as `displaced_batch_count` plus `displaced_batch_digest`; retry verifies exactly the next N journal
events against it. A missing, extra, reordered, or differently serialized caller draft fails closed.
Event-bound report files are never moved. Corrupt/mismatched intents fail closed. This makes a
post-file/pre-event crash recoverable without permanently blocking a later valid report revision.
Before moving any orphan, require `1 <= len(caller_drafts) <= MAX_JOURNAL_BATCH_EVENTS - 1`, because
the repository-authored abandonment event occupies the remaining slot in the same atomic batch.
Fault-inject before/after the combined batch and before/after intent clear; exercise 511 caller
drafts as the accepted boundary and 512 as a pre-mutation rejection; no requested caller event may
be lost or duplicated.

The intent never embeds report bytes and its canonical UTF-8 encoding must be
`<= MAX_REPORT_TRANSACTION_BYTES`. Every open/recovery path pre-stats it and incrementally reads at
most that many bytes before JSON allocation; a larger, nonregular, symlinked, or malformed intent
fails closed without moving files or appending. Add exact-limit/one-byte-over and mutation-spy
tests.

Add a separate `commit_report_revision(...)` method for already-closed engagements. It repeats the
same descriptor/digest/CAS validation, but appends exactly one
`ReportGeneratedPayload(generation_reason="repair_json" | "manual_report")` and never appends
`engagement_closed`. Both methods recognize their deterministic already-committed event after an
`after_event_append` crash and return it idempotently; they reject a conflicting event/digest.
The idempotent lookup shown above must run before stale-CAS rejection: it accepts only the exact
deterministic report ID/revision, original journal watermark, generation reason, both content
digests, and matching confined files. Any partial or conflicting match fails closed. Apply the same
ordering to `commit_report_revision`.
Both repository commit methods repeat the exact JSON/Markdown byte-budget checks immediately after
canonical serialization and before lock, intent, or file IO; they never trust that a caller used

Both use M6A's sole `_append_batch_locked` transaction and therefore publish/advance the same

class ReportClosureFinalizer(ClosureFinalizer):
    def __init__(
        self,
        journal: EngagementJournalService,
        commit_capability: ReportCommitCapability,
        projector: OperationalReportProjector,
    ) -> None:
        self._journal = journal
        self._commit = commit_capability
        self._projector = projector

    def finalize(self, *, snapshot: EngagementSnapshot) -> EngagementSnapshot:
        if snapshot.state.status != "closing" or not snapshot.state.closure_ready:
            raise ValueError("closure barrier is not ready")
        bounded = snapshot.events
        evidence = self._load_all_evidence_descriptors_through(
            snapshot.manifest.engagement_id,
            through_revision=snapshot.revision,
        )
        report_revision = len(snapshot.state.reports) + 1
        report = self._projector.project(
            snapshot=snapshot,
            events=bounded,
            evidence=evidence,
            evidence_reader=self._journal.read_evidence_slice,
            report_revision=report_revision,
            generated_at=bounded[-1].timestamp,
        )
        committed = self._commit.commit_report_snapshot(
            snapshot.manifest.engagement_id,
            report,
            render_operational_report(report),
            expected_revision=snapshot.revision,
        )
        return committed.snapshot

    def commit_later_revision(
        self,
        *,
        snapshot: EngagementSnapshot,
        reason: Literal["repair_json", "manual_report"],

        self,

class ReportManagementService:
    def __init__(
        self,
        *,
        journal: EngagementJournalService,
        finalizer: ReportClosureFinalizer,
        planning: PlanningService,
    ) -> None:
        self._journal = journal
        self._finalizer = finalizer
        self._planning = planning

    def generate_report_revision(
        self,
        engagement_id: UUID,
        *,
        reason: Literal["repair_json", "manual_report"],
    ) -> ReportRef:
        settled = self._planning.settle_pending_evidence(engagement_id, reason="report")
        self._require_complete_settlement(settled)
        snapshot = self._journal.load_snapshot(engagement_id)
        if snapshot.state.status not in {"closed_unverified", "closed_verified"}:
            raise EngagementTransitionError("report_revision_requires_closed_engagement")
        return self._finalizer.commit_later_revision(snapshot=snapshot, reason=reason)

    def regenerate_markdown(
        self,
        engagement_id: UUID,

def _escaped(value: str) -> str:
    return _MARKDOWN_SPECIAL.sub(r"\\\1", html.escape(value, quote=False))


def _code_block(value: str, language: str = "text") -> str:
    longest = max((len(run) for run in re.findall(r"`+", value)), default=0)
    fence = "`" * max(3, longest + 1)
    return f"{fence}{language}\n{value}\n{fence}"
